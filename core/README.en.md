# Rust core

[中文](README.md) | English

`wombat-core` reads local Agent records, creates immutable snapshots, and serves usage and conversation queries from one business model. Codex is the current production source; see the [source acceptance reference](../docs/development/adapters.en.md) for the supported scope.

## Entry points and responsibilities

- `src/adapters/` identifies source facts; `pricing.rs` owns offline prices; `usage_store.rs` writes and reads snapshots; `usage_app.rs` runs shared queries.
- `usage_app_dto.rs` defines requests and results and generates TypeScript and Schema; see the [contracts](../docs/development/contracts.en.md) for field semantics.
- `src/main.rs` accepts one JSON request on stdin and emits one final JSON result on stdout; stage progress goes to stderr.

## Internal business modules

| Business area | Code responsibilities |
|---|---|
| Codex source | `adapters/codex/`: bounded reading, source events, identity facts, direct/cumulative accounting and index titles; the separate incremental entry remains |
| Turn timing | `timing/` and `timing_dto.rs`: fixed-turn analysis, bounded evidence, local/share projections, and a separate per-snapshot result cache |
| Usage queries | `usage_app/`: scope validation, conserved summaries, date/dimension reports and task/turn/step queries; the parent assembles query caching |
| Snapshots | `usage_store/`: immutable generations, exact shard reads and shared live views; each measurement has one ledger attribution |
| Live service | `live/`: incremental collection, revision selection, typed queries and connection/service lifecycle |
| Configuration | `config/`: inventory, scope and evidence queries; scanning separates text/instructions/extensions, while static algorithms separate whole blocks/declared relations/local references |
| Optimization | `optimize/`: deterministic rules, independent outcomes, review service and durable database; user decisions and check facts remain independent |

Only current public contracts and data formats are maintained; unknown formats are rejected without migration. Tests follow the same business groupings and retain independent synthetic expectations.

## Limits and verification

Default refresh reads source logs without changing them and writes only to the product data directory. Unpriced or missing values, partial source failures, and resource limits remain visible; the [architecture](../docs/development/architecture.en.md) and [core rules](AGENTS.md) describe ownership and failure boundaries. After algorithm or storage changes, run the relevant synthetic expectations, formatting, and clippy checks; rebuild the core before cross-language tests.

## Storage and service lifecycle

Configuration views separately pin internal content revisions for configuration measurements, static analysis, and host observations, including the relevant collection completeness and authorization scope. Observation times remain separate; repeating an observation of identical content does not change its content revision solely because time has passed. Default date ranges use the selected view's cutoff. Post-review Skill/MCP observations share use-operation identities and counting semantics within `(review time, view cutoff]`; missing identity, time, dispatch, or target evidence leaves counts unknown. Durable restoration of a unified EvidenceView and public per-object coverage fields remain undelivered.

Static rules cache pure hit/miss judgments using actual parameters, measurement methods, relevant relations and completeness, object identity, and authorization scope; unrelated log appends do not change the dependency key. Each evaluation still checks current availability and comparability with the original review baseline, then binds the current observation time. User decisions and resolution conclusions are not cached. The process-local LRU permits at most 16 entries and 2 MiB of encoding, with 256 KiB per entry. Dependency scans and encoding also have budgets; exceeding them can retain the current judgment but skips reuse and leaves its check identity or dependency basis explicitly unknown, preventing a verified recheck. Encoding allowances are not heap-memory limits, and input preparation and dependency calculation still have costs. The evaluator does not yet expose cancellation.

Rule assessments retain typed measurements, actual thresholds, method versions, dependency content revisions, authorization scope, and cutoff, including for misses. Problem identities use reliable objects or relations and scope, excluding thresholds, whole-file revisions, and check times. Local references and repeated blocks explicitly lack identity when reliable location context is unavailable; names, line numbers, and nearby times do not merge them. The first observation fixes the original object, scope, and assessments as an immutable baseline; rechecks update current facts separately. Only a complete, comparable miss under the same rules, methods, parameters, and scope verifies the original problem. Rule upgrades, missing identity, and missing evidence do not resolve it.

User decisions bind the original problems and supporting checks, while current applicability uses content, relevant dependencies, methods, parameters, and scope. Unrelated log revisions and cutoff changes do not change applicability. Without problem-location identity, a decision applies only to the same complete suggestion version, content, and dependencies, never a new version. Independent handling history lives in `user-v1/reviews.sqlite3`, with current SQLite `user_version=4` and record format version 1. Required version headers are checked before payload shapes. Unknown versions return `UNSUPPORTED_VERSION`; missing headers or corruption in the current format return `REVIEWS_CORRUPT`. Both preserve original data without migration or automatic repair. Rebuilding derived indexes does not clear user decisions or history. Complete U13 acceptance remains in the [rules proposal](../docs/decisions/proposed/architecture/2026-10-04-event-rules.en.md).

Default data directories are `~/Library/Application Support/Wombat` on macOS, `%LOCALAPPDATA%/Wombat` on Windows, and `XDG_DATA_HOME/wombat` or `~/.local/share/wombat` on Linux; `WOMBAT_DATA_HOME` overrides them. Snapshots live in `usage-v4/`, indexes in `live-v2/`; the old `latest.json` is not replaced.

Refresh holds a process file lock, writes a private generation, shards, and hashes, then commits the manifest and atomically updates latest. Cancellation never publishes a partial snapshot. Source failures retain separate receipts; total failure preserves the previous latest. Source reads use the captured length and make no cross-file atomicity claim. Only current formats are supported; unknown versions are rejected without automatic migration or deletion.

Safe events use exact `threadId` and optional `turnId` partitions, retaining facts without a task or turn separately; the event index has its own version. Blocks obey both a 200-fact limit and a 4 MiB limit on the complete encoding, with hash, attribution, order and count validation. A single event plus block metadata exceeding 4 MiB fails explicitly with a resource error and preserves the previous latest. Memory and disk use the same block index; exact-target queries read only intersecting event blocks. Whole-target reads allow at most 100,000 facts, evidence pages at most 200 rows, and each query at most 64 MiB of block encodings; the event array encoding obeys the same byte limit. Queries support cancellation; page cursors bind the snapshot, exact target and partition-index hash. Limits or failed validation never return a truncated success.

Per-file read watermarks retain source identity, file generation, the committed complete-newline boundary, captured length, collection time, and coverage state through index restoration and snapshot export. Collection time does not replace event time; unchanged files retain their original observation time. Incremental reads do not commit incomplete tails. Ordinary reads retain valid records without a final newline while reporting incomplete coverage. Missing files or individual source failures retain prior positions. Mixed success marks failures only in a new view; total failure rolls back without changing the old view or separately persisting that failed attempt. Watermarks remain internal facts; timing summaries expose coverage counts without exporting their raw fields.

The Rust snapshot API `timing_evidence` reads canonical measurements and operations, exact-turn events, relevant unattributed discontinuities, and read watermarks for an explicit source, thread, and turn. Operation attribution is validated against the actual owner; queries neither pair events again nor traverse the ledger or unattributed buckets. Memory and disk share budgets of 100,000 touched facts, 64 MiB of encoding, and 100,000 metadata work units; all limits apply together. Limits, cancellation, or failed validation return errors rather than truncated success. Required per-thread metadata records potential Skill/MCP operations without a turn during the same writer pass. Unknown metadata versions are rejected; missing current-format fields are corrupt, and original snapshots remain intact.

Codex message events retain only provenance, content presence, native identity, and record phases, without bodies, lengths, content hashes, or media addresses. Presence uses the original string; whitespace-only strings are nonempty. First-content-record delay uses the logged timestamps of an explicit turn start and the first known nonempty visible assistant record, and is distinct from time to first token. Earlier unknown content, missing times, identity or cross-file ordering conflicts, and relevant source discontinuities prevent calculation. Invalid records after a file generation is established retain safe discontinuities; incremental incomplete tails are not committed. Restoration and appends require the current message-observation mapping version. Missing or unknown versions reject reuse while preserving the original index, preventing old intermediate results without message markers from being mixed in. Strict response gaps remain unsupported because tool-batch and response-cycle evidence is missing.

Construction still retains all E safe events in O(E) memory and sorts in O(E log E); snapshot loading reads the complete manifest metadata, and watermark metadata grows with the number of source files. Full-source residency and total persistence limits remain undelivered.

The typed `timing` operation returns whole-turn summaries, safe evidence pages, or parser capabilities; capabilities require no source scan. Evidence collections are explicitly `turn_events`, `use_objects`, or `use_records`; cursors bind the snapshot, source, thread, turn, collection, optional object, and methods. Public fields derive from the [Rust DTO](src/timing_dto.rs) and [generated schema](../docs/schemas/timing-response-v1.schema.json). Fixed snapshot queries remain offline and bypass price refresh, configuration, Hooks, and account reads. Summary output is limited to 256 KiB. Full-partition native boundary indexes preserve independent duration/TTFT/state observations when fact reading exceeds its budget; conflicts remain explicit. The shared reducer retains at most two distinct value witnesses and 100,000 clock domains, taking O(E log min(D,100000)) construction time and O(min(D,100000)) auxiliary space for D clock domains. Domain overflow hides absolute anchors while preserving independent native scalars.

Context detail above its 32-segment/neighbor budget is omitted as unavailable without truncating full-scope distributions. Local results use a per-snapshot 16-entry/2 MiB encoded cache, at most 256 KiB per entry including keys; freshness is rebound on each call, and partial, running, oversized, or sharing results are uncached. Sharing is a separate Rust whitelist with relative time and fresh package aliases, without local read identities, paths, or custom names. Record/candidate/interval loops check cancellation; bounded sorting stages remain cooperative rather than preemptible. Command labels, whole-turn operation totals, and file-change metrics remain undelivered; strict response gaps stay unsupported.

Skill/MCP object summaries reuse the shared operation classification, canonical identity, and count rules. Failed operations count; declarations and discovery do not establish use, and candidates remain candidates. Missing identity, dispatch, target, or turn evidence keeps affected counts unknown. Associated counts and source completeness are separate: zero describes only the captured scope. Missing operation times remain explicit without inventing dispatch times. Local summaries show the first 50 objects, ordered by known associated count and stable object key; object and per-operation pages contain at most 200 rows without changing whole-turn totals or coverage. Paths, server names, historical projects, records, and cursors are local only; sharing exposes numeric totals and coverage. Projection allows at most 100,000 operations and 64 MiB of inspected strings. A failed complete projection yields unknown use metrics, never a prefix. Use details have a separate 128 KiB limit; detail overflow or pressure on the 256 KiB summary removes use details and cursors first, retaining verified totals, time, and context. Multi-target parsed command reads remain subsequent delivery work.

Rust projects validated lifecycle intervals as relative category tracks and merges adjacent regions with mask 0 as unclassified gaps, without stretching native durations. Tracks retain references to endpoint and terminal events from the same domain; gaps refer to the whole-turn evidence collection. Track and gap details share a 200-entry limit: overflow omits the entire detail while retaining complete totals and counts. Running turns, missing reliable anchors, unsafe numeric ranges, and detail overflow select list presentation. Lists also take priority when unlocated intervals exceed half of unique identified lifecycle intervals; records without identity stay in separate coverage counts. Share output uses fresh package aliases and relative coordinates. Local summaries bind each interval alias to fixed evidence page cursors; support references on the same page are merged within that interval. Navigation uses the already read exact event order, with at most 600 selected identifiers, and reads no additional event blocks. A separate 64 KiB encoding limit omits all locators on overflow while preserving verified counts. Page counts sum locator references across intervals, including repeated pages. Missing computation or proof remains unknown; sharing contains no cursors.

The live index commits facts, cursors and projections together using integer keys and JSONB. Equal projections and prices share storage; see the [index decision](../docs/decisions/implemented/architecture/2026-10-02-compact-live-index.en.md) for boundaries. Truncation/replacement rebuilds; disappearing files retain contributions and mark partial. Sources roll back independently, and all-source failure retains the prior view. Fixed queries and caches are isolated by revision/scope. Parser facts recover by replaying stored events; read projections remain disposable caches, checkpoints retain parser context and source diagnostics, and titles still come from the external session index. Unchanged metadata takes a fast path that does not read log contents; it cannot detect an edit whose original timestamp is restored, while explicit verification rechecks the file. Changed or explicitly verified files use a 64 KiB buffer to check the committed prefix and verify the captured contents before and after parsing; a source change during observation rejects publication and triggers a retry. Changed files require two full-content validation passes plus parsing of new content, taking O(captured file length); continued writes may delay completion until a stable read is possible. This integrity check is not a performance improvement. Replay sorts E events in O(E log E) time and retains all events in memory. Direct-response appends skip cumulative reconciliation, and turn queries borrow facts. Full traversal and rebuilding remain; persistent MVCC, database aggregation and long-term scale targets are undelivered.

Snapshots exclude message bodies, complete command arguments, and tool output; source data is never an instruction. The on-demand core service still uses a private Unix socket or owner-only Windows named pipe and exits about 15 seconds after its last call when no valid configuration view remains. HTTP exists only in the explicitly started Web host. Permanent monitoring and HTML report export are unavailable.
