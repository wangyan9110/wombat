# Rust 内核

中文 | [English](README.en.md)

`wombat-core` 读取本机 Agent 记录，生成不可变快照，并为用量与对话查询提供同一业务口径。当前生产来源为 Codex；具体支持范围见[来源适配参考](../docs/development/adapters.md)。

## 入口与职责

- `src/adapters/` 识别来源事实；`pricing.rs` 负责离线价格；`usage_store.rs` 保存与读取快照；`usage_app.rs` 执行共享查询。
- `usage_app_dto.rs` 定义请求和结果，生成 TypeScript 与 Schema；字段语义见[契约](../docs/development/contracts.md)。
- `src/main.rs` 通过 stdin 接收一条 JSON 请求，在 stdout 输出一条最终 JSON 结果；阶段进度走 stderr。

## 内部业务模块

| 业务 | 代码职责 |
|---|---|
| Codex 来源 | `adapters/codex/`：读取和边界、事件解析、身份事实、直接/累计计量对账、索引标题；独立增量入口保留 |
| 轮次耗时 | `timing/` 与 `timing_dto.rs`：固定轮次分析、有界证据、本地与分享投影，以及独立的快照结果缓存 |
| 用量查询 | `usage_app/`：范围校验、守恒汇总、日期/维度报表、任务/轮次/步骤；父入口装配查询缓存 |
| 快照 | `usage_store/`：持久代次、精确分片读取、共享内存视图；账本只有一个计量归属 |
| 实时服务 | `live/`：增量采集、读取版本选择、类型化查询、连接与服务生命周期 |
| 配置 | `config/`：盘点、范围、证据查询；扫描按文本/指令/扩展拆分，静态算法按完整块/声明关系/本地引用拆分 |
| 优化 | `optimize/`：确定性规则、逐规则结果、处理记录服务和持久数据库；用户决定与检查事实分别保存 |

拆分保持公开导出、协议版本、快照和用户记录格式。测试按同一业务分组，继续使用独立合成真值。

## 限制与验证

原生日志总输入可独立于缺失的缓存细分展示。缓存命中率使用同一批记录的总输入与缓存读取量；逐条分类矛盾时不显示命中率，原生输入冲突不会通过分类求和恢复。

计量观察按字段保留模型、模型提供商、API 提供商和推理强度冲突，继承、追加及重放不会清除同一响应的冲突。影响定价的冲突保留 Token，但不选择模型费率；仅推理强度冲突不阻止计价。分档价格要求已记录的单次请求输入，不从可能冲突的分类重建。解析状态、投影和固定快照要求计量观察映射版本 2；不兼容版本拒绝复用并保留原数据。

默认刷新只读来源日志，写入限于产品数据目录。无价、缺失、部分来源失败与资源上限需保持可见；详细责任和故障边界见[架构](../docs/development/architecture.md)与[内核约定](AGENTS.md)。修改算法或存储时运行对应合成真值、格式和 clippy 检查；跨语言测试先重建内核。

## 存储与服务生命周期

观察版本的字段名和值由共用描述符维护。解析状态和实时投影使用同一组头读写规则；内存与磁盘快照使用同一份类型化头构造，磁盘字段保持不变。各入口仍在读取负载或复用缓存前检查所需观察版本头；水位、存储格式和分析方法保留独立版本。

配置读取版本分别固定配置测量、静态分析和宿主观察的内部内容修订，采集完整性与授权范围参与对应修订；观察时刻单独保留，重复观察相同内容不会仅因时间变化而改写内容修订。默认日期范围按所选视图的截止时间解析。复查后的 Skill/MCP 观察复用使用操作的身份与计数口径，时间范围为 `(复查时间, 视图截止时间]`；缺身份、时间、派发或目标证据时保留明确关联的次数，并用 partial 说明完整计数受限。读取视图保存在内存中，最长十分钟，进程重启后过期；过期明确失败，不回退到更新观察。配置对象与后续观察公开同一方法 3 投影生成的 `useBasis`：固定快照、观察截止、所选来源/项目/任务/Agent 范围、时间窗口、派发/身份/目标/时间/轮次五维缺口及所选来源采集完整性。来源操作时间可能来自结果记录，不等同于派发时刻。已知零值仅描述已采集范围；有缺口的可运行投影仍返回已观察次数；不可用历史的次数与缺口维度为 null。配置中的规则加载/读取与后续观察中的规则文件读取保留不同单位。当前配置不能证明历史加载或内容。

只读的 `optimize activity` 提供五个固定轮次检查：失败后再次调用、同目标成功读取后的重读，相同请求再次出现，以及失败占比和请求输入变化。它复用共用重复行为次数及证据引用。受支持的正向次数在覆盖不完整时仍可命中；零值只有在该次数所需覆盖完整时才表示未发现。可选耗时缺口不使次数失效。缺少执行顺序时不能确认前驱关系，但仍保留请求记录。五个检查事实均保留；已有确认的再次调用或重读线索时，不再重复显示泛化请求建议。失败占比检查直接读取同轮次的操作结果统计，采用 `terminal_failure_inspection_v1`：至少 5 次结果可判定的操作、2 次失败，且比例不低于 40% 才给出建议。比例仅针对已采集的结果可判定子集；低于阈值只表示当前子集未达到检查条件，不证明整个任务没有问题。样本较少时保留统计并解释，不生成该建议；部分来源仍可给出限定范围的正向建议。检查带有原统计及固定阈值，不重读来源或重选分母。优化响应版本 4、活动格式 3 隔离旧结果，不改变用户决定格式。这些是供检查的线索，不代表故障、浪费、节省或解决。响应编码预算为 256 KiB。此路径不采集配置或宿主钩子，不刷新价格，也不写复查记录。

规则在共用证据目录中声明自己的读取门槛。文件大小检查可使用本次授权采集的文件系统元数据，即使正文未读到；正文、格式和引用检查仍要求各自的有效内容。正文不足不会把未支持的算法改称证据不足。来源或检查方法改变时，复查仍要求同口径比较。

静态规则按实际参数、测量方法、相关关系与完整性、对象身份及授权范围缓存纯命中/未命中判断；无关日志追加不改变依赖键。每次仍检查当前可用性和原复查基线的可比性，再绑定当前观察时间，不缓存用户决定或“已解决”结论。进程内 LRU 最多 16 项、2 MiB 编码，单项最多 256 KiB；依赖扫描与编码也有预算；超限可保留当前判断，但跳过缓存并明确检查身份或依赖依据未知，不能据此完成复查验证。编码额度不代表实际堆内存上限，输入准备与依赖计算仍有成本；评估器尚无取消接口。

规则检查保存类型化测量、实际阈值、方法版本、依赖内容修订、授权范围和截止时间，未命中也保留这些依据。问题身份按可靠对象或关系及范围生成，不包含阈值、整文件修订或检查时间；本地引用与重复块缺少可靠位置上下文时明确身份未知，不按名称、行号或相近时间合并。首次观察即固定原始对象、范围和检查基线，后续复查仅更新当前事实。只有相同规则、方法、参数和范围下证据完整、可比的未命中才标为已验证；规则升级、缺身份或缺证据不会解决原问题。

用户决定绑定原问题及支持检查，同时以内容、相关依赖、方法、参数和范围检查当前适用性；无关日志修订和截止时间变化不改变适用性。问题位置身份未知时，决定仅适用于同一完整建议版本、内容和依赖，不跨新版本继承。处理记录独立保存在 `user-v1/reviews.sqlite3`，当前 SQLite 格式为 `user_version=4`，记录格式为版本 1；必需版本头先于载荷形状校验。未知版本报 `UNSUPPORTED_VERSION`，当前格式缺头或损坏报 `REVIEWS_CORRUPT`，均保留原数据，不迁移或自动修复。重建派生索引不清除用户决定和历史。完整 U13 验收仍见[规则提案](../docs/decisions/proposed/architecture/2026-10-04-event-rules.md)。

默认数据目录为 macOS `~/Library/Application Support/Wombat`、Windows `%LOCALAPPDATA%/Wombat`、Linux `XDG_DATA_HOME/wombat` 或 `~/.local/share/wombat`；`WOMBAT_DATA_HOME` 可覆盖。快照位于 `usage-v4/`，索引位于 `live-v2/`；不替换旧 `latest.json`。

刷新持有进程文件锁，先写私有 generation、分片与哈希，再提交 manifest 并原子更新 latest；取消不发布半份快照。单源失败保留独立回执，全部失败保留旧 latest。源日志按本次长度读取，多文件不声称原子一致。只支持当前格式，未知版本拒绝，不自动迁移或清空。

安全事件按精确的 `threadId` 与可选 `turnId` 分区，分别保留无任务和无轮次的事实；事件索引独立标明版本。块按最多 200 条事实和 4 MiB 完整编码双重上限切分，并校验哈希、归属、顺序和数量。单条事件连同块元数据超过 4 MiB 时明确报资源失败，保留旧 latest。内存与磁盘使用同一分块索引；精确目标查询只读取触及的事件块。整目标读取最多 100,000 条事实，证据页最多 200 条，每次查询最多读取 64 MiB 块编码，事件数组编码也受此字节上限约束。查询支持取消；分页游标绑定快照、精确目标与分区索引哈希，超限或校验失败不返回截断成功。

每文件读取水位记录来源身份、文件代次、已提交完整换行边界、捕获长度、采集时间及覆盖状态，并随索引恢复和快照导出保留。采集时间不代替事件时间；未变化文件沿用原观察时间。增量读取不提交半尾行；普通读取保留合法但无结尾换行的记录，同时报告读取不完整。文件消失或单源失败保留此前位置；混合成功只在新视图中标记失败，全部失败回滚且不改旧视图，也不单独持久化此次失败尝试。水位仍为内部事实；耗时摘要展示覆盖计数，不导出水位原字段。

Rust 快照接口 `timing_evidence` 按明确的来源、任务和轮次读取规范计量与操作、精确轮次事件、相关未归属断点及读取水位。操作归属与实际所属任务校验；查询不重新配对事件，也不遍历账本或未归属桶。内存与磁盘共用最多 100,000 条触及事实、64 MiB 编码和 100,000 次元数据工作预算，各项同时生效。超限、取消或校验失败返回错误，不返回截断成功。写入时在同次遍历中记录任务内缺少轮次的潜在 Skill/MCP 操作，作为必需元数据。未知元数据版本拒绝读取；当前格式缺少字段视为损坏，保留原快照。

Codex 消息事件只保留来源类别、内容是否为空、原生身份和记录阶段，不保留正文、长度、内容哈希或媒体地址。内容非空按原始字符串判断，空白字符串仍算非空。首条内容记录延迟使用明确轮次开始与首条已知非空可见助手记录的日志时间，不等同于首 Token 时间；较早的未知内容、缺时间、身份或跨文件顺序冲突、相关来源断点会阻止计算。已建立文件代次后的坏记录保留安全断点，增量半尾行不提交。恢复和追加要求当前消息观察映射版本，缺失或未知版本拒绝复用并保留原索引，防止混用不含消息标记的旧中间结果。严格响应间隙仍因缺少工具批次和响应周期证据而不支持。

构建仍需全部 E 个安全事件驻留，内存为 O(E)，排序为 O(E log E)；加载快照仍读取完整 manifest 元数据，水位元数据随来源文件数增长。整源驻留与持久化总量上限尚未交付。

类型化 `timing` 操作返回整轮摘要、安全证据页或解析器能力；能力查询不扫描来源。证据集合明确为 `turn_events`、`use_objects` 或 `use_records`；游标绑定快照、来源、任务、轮次、集合、可选对象及方法。公开字段以 [Rust DTO](src/timing_dto.rs) 和[生成 Schema](../docs/schemas/timing-response-v6.schema.json) 为准。固定快照查询保持离线，不触发价格刷新、配置、Hook 或账户读取。摘要输出最多 256 KiB。完整分区的原生边界索引在事实读取超限时保留独立的耗时、首 Token 时间及状态，并明确保留冲突。共用归约器最多保留两个不同数值依据及 100,000 个时钟域；对于 D 个时钟域，构建时间为 O(E log min(D,100000))，辅助空间为 O(min(D,100000))。时钟域超限时绝对锚点未知，独立原生数值仍可保留。

上下文详情超过 32 个分段或邻近记录时整体标为不可用，整轮分布不截取前缀。本地结果按快照缓存，最多 16 项、2 MiB 编码，单项连同键最多 256 KiB；每次重新绑定新鲜度，部分、运行中、超限与分享结果不缓存。分享由 Rust 独立白名单生成，使用相对时间和每次新建的包内别名，不含本机读取身份、路径或自定义名称。记录、候选和区间循环检查取消；有界排序阶段仍为协作取消，不能抢占。操作仅统计日志已观察到的范围，不能覆盖未记录活动；命令语义标签与严格响应间隙仍不支持。

请求输入变化使用 `request_input_observation_change_v1`，比较同一物理来源代次、任务、轮次及历史模型/推理强度阶段内首末请求的 `rawInput`，含缓存输入。按日志观察位置排序，不要求时间或窗口大小；不证明执行顺序、持续增长或实际上下文占用。压缩、历史模型声明切换及来源断点切断阶段。区间计量、缺输入、历史阶段或位置不明、冲突及越界数量分别排除；精确重放计一次，一个计量出现在不同位置时不任意选序，同一行多个请求不互相排序。至少两个可靠样本才可比较。保留首末量、带符号差值及非零基数的倍数；零基数不产生倍数。完整阶段计数和最大正向增加不受 32 项、32 KiB 编码明细预算影响，省略明细单独说明。没有可比较阶段时不补零；可比较阶段没有正向增加时最大增加为零。`request_input_change_inspection_v1` 以首末增加至少 16,384 Tokens 为检查门槛，这是产品启发式，不是浪费、因果或节省结论。规则、CLI、Web 和分享复用同一统计；规则不重读日志，不写用户决定。

Skill/MCP 对象摘要复用共享的操作分类、规范身份与计数口径。失败操作计入次数；声明与发现不能证明使用，候选仍为候选。缺身份、派发、目标或轮次证据时仍保留已关联次数，完整次数则按缺口解释；目标冲突的规范操作不计入任一对象。已关联次数与来源完整性分别展示，零值仅描述已采集范围。缺操作时间单独保留，不补造派发时间。本地摘要显示前 50 个对象，按已知关联次数与稳定对象键排序；对象和逐次操作分页最多 200 行，整轮总数与覆盖不随分页变化。路径、服务器名、历史项目、操作记录与游标仅限本地；分享只公开数值总计与覆盖。投影最多处理 100,000 个操作和 64 MiB 被检查字符串；完整投影失败时使用指标未知，不返回前缀。使用详情另限 128 KiB；详情超限或整份摘要触及 256 KiB 时，先移除使用详情与游标，保留已验证总计、时间和上下文。原生命令解析读取在同一个规范操作上保留多个候选目标；终态结果不能证明各目标已独立读取，用户 Shell 记录也不能证明模型使用。

操作结果优先使用结构化终态证据：已结束的工具输出带可靠退出码 0 时可确定完成；开始记录带 0、正文中的退出码文字或缺少结果不能证明完成。失败、拒绝和中断不会被后续成功标记覆盖；拒绝作为独立使用结果传给 CLI/Web。同一操作的可靠结果互相矛盾时，持久保留冲突标记及负面证据，并省略无法确定的单一退出码；重放不能清除冲突。解析状态、派生投影与固定快照要求操作观察映射版本 4，缺失或不支持的版本在读取事实前拒绝，保留原数据而不自动迁移。

工作摘要消费同一份有界规范操作，每个可靠身份只计一次，并明确保留缺身份、终态冲突、资源超限和来源覆盖。已闭合观察包含完成、失败、取消、中断和拒绝；失败不扣减候选数。文件变更记录按规范文件操作计数，包含未闭合观察。不同文件路径数包含终态变更映射 的路径和移动端点，也包含失败或拒绝结果；它只描述来源报告范围，不证明落盘或仓库净 diff。拟议变更映射、元数据不完整，或相对路径缺可靠操作 cwd 时，路径数保持未知。绝对路径只作词法规范化，不读取文件系统或解析符号链接；任务项目不能补缺失 cwd。增删行数需要仓库基线，仍不可用。用户输入、注入上下文和推理计数描述精确轮次内的物理安全记录，不是消息数、请求数或注入轮数。用户来源未分类时，用户输入记录数未知；未归属记录及部分来源通过覆盖信息保留。工作投影检查取消，最多处理 100,000 个操作、100,000 次元数据工作和 64 MiB 被检查字符串。必需身份预算超限时省略工作计算；可选元数据预算超限时省略相关工作数值，保留已完成的操作结果统计和独立时间结果。

操作结果统计另有明确的子集口径：成功与失败终态的规范操作数构成分母，失败数构成分子。完成状态且可靠退出码非零计为失败；中断、取消、拒绝、未结束、未判定及结果冲突分别计数，不补为成功。非零退出码但没有可判定终态的操作不进入比例。目标、时间和文件元数据缺口不排除可靠结果；冲突结果不选取任何一份作为比例依据。缺身份按物理记录计数，其他类别按规范操作组计数；声明和未确认调用候选不参与。比例仅描述已采集且结果可判定的记录，零分母不产生比例，来源不完整及结果缺口独立说明。旧失败操作数可保留冲突中的负向观察，不能复用为比例分子。公开耗时响应版本 6、分析方法 `safe_event_turn_v7` 和工作投影方法 2 隔离旧缓存；CLI、Web 和分享使用同一份统计结果，分享不带本地身份。

时间分析方法 `safe_event_turn_v7` 包含命令、压缩、推理和 MCP 四类，交集掩码为 0—15。原生 Item 与安全操作阶段共用起止证据归并入口；call 与 item 身份分域，仅显式别名或同一来源物理行的匹配标识可建立桥接。原生端点优先于记录时间，只有原生时长而缺端点的操作仍保留标量，不用时长倒推时间轴位置。MCP 完成标记只证明闭合，不单独证明调用成功。操作投影与时间阶段使用核心共享关联入口，调用目标或执行结果矛盾不否定一致的时间端点，按独立原因解释。原生条目完成只证明闭合；成功与失败来自结构化操作结果。完整的字段观察与分析契约仍按[架构修订](../docs/decisions/proposed/architecture/2026-10-05-analysis-first-events.md)继续收敛。

Rust 将已验证的生命周期区间投影为相对时间类别轨道，并把相邻的 mask 为 0 的区间合并为未分类间隙，不拉伸原生耗时。轨道保留同域端点及终态的事件引用；间隙引用整轮证据集合。轨道与间隙共用 200 条详情上限，超限时整体省略详情，保留完整汇总和条目数。运行中、缺可靠锚点、数值越界或详情超限时选择列表展示；未定位区间超过具备身份的唯一生命周期区间半数时也以列表为主。缺身份记录保留在独立覆盖计数中。分享使用每次新建的包内别名和相对坐标。本地摘要将每个区间别名绑定到固定证据页游标，同一区间内同页支持引用合并。导航复用已读取的精确事件顺序，最多保留 600 个选中身份，不额外读取事件块。导航编码独立限制为 64 KiB，超限整体省略定位信息，保留已证实的计数。页数按各区间的定位页引用合计，重复页面仍分别计入。缺计算或依据保持未知；分享不含游标。

操作补集 `operation_residual_v1` 复用共享起止归并及现有区间并集算法，按显式轮次窗口减去可靠闭合的操作区间；推理和压缩生命周期单列。它保留候选操作、可靠端点、身份缺口、冲突与部分覆盖；没有可配对操作时不宣称模型等待。明细超过 200 项只省略细节，保留完整计算值。公开耗时响应、CLI 和 Web 展示并集、补集、配对计数、覆盖说明及有界相对区间；后续重复行为指标与最终验收见[指标方案](../docs/decisions/proposed/architecture/2026-10-04-event-metrics.md)。

匹配观察方法 2 保存在共用操作上，与命令工作元数据分开：命令使用受支持的完整原生 argv 与历史 cwd 生成请求指纹，保留来源线程内代理执行归属及已校验的历史词法读取目标。直接 argv 和不含展开、管道或串联的字面 shell 请求可匹配；未知执行参数、插件/脚本上下文和交互输入不建立匹配；命令原文只在内存处理，使用现有 shlex 库解析，参数最多 1,024 项、64 KiB。读取目标还需原生 Read 标签与受支持的 cat/head/tail/数字范围 sed 调用一致，重复目标只保留一次。目标按来源 POSIX/Windows 路径规则处理，不查当前文件；父级路径、远端 URI 及不确定参数保留缺口。指纹仅说明请求相同，不证明二进制、环境、输入版本或效果相同；搜索类预期非零另列。工作观察映射 4、操作映射 4 和适配器 codex-rollout-9 拒绝复用旧观察，但保留旧数据。此观察已接入再次调用/重读分析及 CLI/Web 汇总投影；固定轮次检查已消费这些共用结果；确切交付范围及历史版本仍待来源证据。

有明确服务器/工具身份的原生 MCP 条目及旧式 begin/end 调用复用同一匹配观察和归并器。完整参数对象只在内存生成摘要，参数值、资源 URI 与结果正文不落盘。现有 serde_json 对嵌套对象键排序并统一字符串转义，启用任意精度以避免数值舍入造成误匹配。数组顺序、参数是否存在和数值差异仍参与匹配；等价指数写法可能被统一。重复键、库保留的数值标记、未支持的请求上下文字段、损坏参数不建立原生匹配。限制为 64 KiB、4,096 个节点及 32 层；超限时整体省略指纹。完成记录缺参数可以保留派发时的匹配事实，冲突一经记录不会被后续记录消除。必须有明确来源线程执行归属；MCP 不提供文件系统读取目标或命令预期退出码。完整的模型函数请求另保留摘要，包含确切命名空间、调用名称及完整参数对象。旧式编码 MCP 名称、明确 MCP 命名空间及内置资源/发现名称均可使用此路径，不反解原始服务身份。函数请求必须有明确调用 ID 和受支持的完整字段结构；损坏、重复键、未知上下文或超限请求不提供摘要。参数和 URI 仅在内存处理。规范归并优先使用已有原生摘要，否则使用函数请求摘要；不将两种摘要当作相等依据。同一操作任一种摘要发生冲突时保留不可清除的冲突。函数匹配不能补造服务器归属，不能将发现算作用过，也不能将调用结束算作成功；公开的合格命令计数仍只统计命令。

再次调用/重读方法 1 复用同一次操作关联及起止归并，分别统计固定来源顺序中的额外请求记录，以及有可靠执行顺序的确认关联。没有时间或明确成功仍能统计请求记录，但来源顺序不证明执行顺序。失败后再次调用要求最近的相同请求已失败，并在后次发起前完成；重读确认要求此前有同目标读取已成功，并在后次发起前完成；其间的失败或结果不明请求不抹除已观察到的成功。只有相对发起顺序不含歧义时，单独完成记录才能建立前驱。用户输入、压缩、分叉关系和来源连续性缺口切断链；不支持匹配的命令或 MCP 请求也保守切断。跨越上下文、执行归属缺口、元数据矛盾和发起顺序歧义保留覆盖说明。原生时长优先于成对起止计算时长，原生时长冲突不补成计算值；已知小计与缺少时长的次数分开，恢复跨度单列。同一操作的两个标签只进入一次合并区间并集。明细超过 200 个匹配操作或 600 份来源记录依据时只省略细节，保留完整合计；操作/元数据/字符串预算不足则放弃整次计算，不返回截断前缀。耗时响应 6 公开次数、已知耗时小计及原生/计算/缺失次数、恢复跨度、去重覆盖时间与类型化覆盖说明。本地和分享结果分别构造，不序列化匹配键、执行归属、目标路径或原生前驱身份。汇总指标证据指向整轮记录集合；本地前驱导航使用摘要内别名及精确安全记录页游标，分别定位后次调用、前次失败和前次成功读取，始终绑定同一固定数据视图。依据包含匹配、结果、耗时及起止记录，每份最多 16 个事件引用。独立 64 KiB 编码预算超限时整体省略依据明细，保留完整计数与时间总计；摘要输出不足时，先移除这些导航再考虑汇总事实。分享不构造或包含这些定位信息。更强的读取范围/版本，以及未映射的恢复/分支边界仍需来源观察；最终验收保留在指标方案。

共享操作关联按来源、线程和轮次隔离 `Call`／`Item` 身份，显式桥接可合并两个已存在的组并撤回旧派生贡献；文本相同本身不建立关联。来源事件的原始身份不改写，派生操作尽量保留固定来源顺序中最早的操作身份。关联方法独立版本 `operationAssociationVersion=1` 由解析状态、实时投影和固定快照共同校验，缺失或不支持时保留原数据并拒绝复用。每次受影响来源完成采集后执行一次关联，时间为 O(E log E)、附加空间为 O(E)；普通追加只写变化操作，身份撤回时在现有事务内替换该来源的操作与别名投影。此处统一计算语义，不承诺减少全源驻留。

实时索引以整数键和 JSONB 同事务保存事实、游标和投影；相同投影及计价共享，边界见[索引决定](../docs/decisions/implemented/architecture/2026-10-02-compact-live-index.md)。截断/替换重建，文件消失保留贡献并标 partial；来源独立回滚，全部失败保留旧版。固定查询及缓存按版本/范围隔离；解析事实由已存事件重放恢复；读取投影仍是可重建缓存，checkpoint 保留解析上下文与来源诊断，version 1 外部标题观察独立于会话事件保存，可在重放和固定视图中恢复；标题索引成功完整读取时反映标题变更或移除，读取失败则保留仍有对应线程的安全观察并报告缺口。安全事件格式 3 独立保存逐事件采集时间，不补缺失发生时间；追加、重启和同代次校验重读保留既有采集时间。消息观察映射 2 把格式无效的嵌套记录保存为同来源位置和已知范围的缺口，后续已知内容不能补成精确首条延迟。未知类型的嵌套项保留未知内容标记，已知非内容项不算内容候选。解析/投影和固定快照的必需观察版本头拒绝旧格式并保留数据。元数据未变时走快速路径，不读取日志正文；因此不能识别元数据未变但内容被改写后又恢复原时间戳的情况，显式 verify 会重验。变更或显式 verify 的文件使用 64 KiB 缓冲校验已提交前缀，并在解析前后校验本次捕获内容；观察期间来源变化则拒绝发布并重试。变更文件需完整读取两遍作校验并解析新增内容，时间为 O(捕获文件长度)，持续写入可能延迟到获得稳定读取机会；此完整性检查不构成性能提升。重放排序 E 个事件需要 O(E log E) 时间，内存仍保留全部事件，校验重建另暂存 O(E) 个事件身份与采集时间。逐响应追加跳过累计归并，轮次借用事实。仍需全量遍历及重建，持久 MVCC、数据库聚合和长期规模目标未交付。

快照不含消息正文、完整命令参数或工具输出，来源数据不作为指令。本机内核按需服务仍使用私有 Unix socket / 所有者专用 Windows 命名管道，无有效配置读取版本时，最后调用后约15秒退出；HTTP 只存在于显式启动的 Web 宿主。尚无永久监控或 HTML 报告导出。
