# Support matrix

[中文](support-matrix.md) | English

Current implementation covers usage, conversations, configuration analysis, user decisions and direct rechecks. Core and former CLI/TUI verification is recorded in [progress](../project/progress.en.md). CLI and local Web are the current entries; TUI has been removed; see [implementation status](../project/status.en.md). Historical terminal tests do not replace new-interface acceptance, and historical commands are not current support.

See [adapter cases](../development/adapters.en.md) for source boundaries and independent acceptance cases, and [pricing](pricing.en.md) for price rules.

Not delivered: full optimization-lifecycle acceptance, installation acceptance on other platforms, other production agent adapters, guaranteed coverage of all historical formats, model-quality/causal diagnostics, actual subscription invoices, desktop, permanent background monitoring, HTML reports, and evidence-package export. New work must not reintroduce retired product entries.

Explicit Markdown local references check existence/type and authorized boundaries, with independent rule outcomes exposed through CLI/Web. Older views retain original observations; dynamic paths and access gaps do not become missing-file findings.

Threshold revision: Skill full/body measurements are independent; description product/specification checks are graded. Rule versions and parameters are saved with review evidence. Loading-budget,30-day complete observation and14-day worktree running/protection/recovery adapters remain unsupported; gaps never generate suggestions. See [specification](../project/config-upgrade.en.md).

Optimization suggestions use real related-record queries, showing counts/turn tokens/estimated API cost together, preserving filters across exact-turn round trips and comparing measured text after manual rechecks. Dates filter related records only; coverage gaps, missing associations and unknown usage stay explicit, without demo savings or automatic execution.

Verified review records separately show awaiting follow-up task verification. Natural associations use the original recheck time and project/source, distinguishing no observation, unknown versions and unavailable history. CLI/JSON and Web share the result. File changes do not imply adoption; positive statements or targeted reads form only approximate “observed use” and do not prove that Skill instructions were followed. Exact invocation and runtime recurrence remain unfinished.

See the [specification](../project/startup-rules.en.md) for startup/static-rule support: Web shell/preferences, waiting/older results, host background prices, discovered task metadata, and explicit storage faults. Exact full-paragraph/list duplicates, user-declared chains, and identity-v1 copy drift share CLI/Web results. AGENTS.md has native Codex log load evidence. Hook project registry observations for Codex0.160.0 file declarations have an adapter; Unix has bounded static script-reference checks; standalone/inline plugin JSON declarations and native-expanded static paths bind identity, file versions and authorized projects. Remaining dynamic expressions stay unknown, while Windows commands and actual Hook injection/execution remain incomplete. Resource limits cannot count as a passing recheck.

The unreleased first version maintains only current formats, without migration or compatibility for old snapshots, indexes or pages.

Current static-config-v7 rules retain v4 recheck and shared-configuration constraints: same-local-path objects aggregate while preserving per-source evidence and overlapping authorization memberships. Unknown applicability and absent declarations cannot pass. User review records share evidence and page in SQLite, initializing only the current database format and rejecting unsupported formats; see [contracts](../development/contracts.en.md) for format and resource boundaries.
