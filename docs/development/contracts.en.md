# Public contracts

[中文](contracts.md) | English

Rust `core/src/usage_app_dto.rs` defines requests and responses; `adapters/contract.rs` defines source-independent facts; `pricing.rs` defines decimal amounts and their basis.

Generated files:

- [Live request schema](../schemas/live-request-v1.schema.json) and [live response schema](../schemas/live-response-v1.schema.json), sourced from `core/src/live.rs`; `live` wraps v3 results with independent freshness metadata.
- [Request schema](../schemas/usage-request-v3.schema.json)
- [Response schema](../schemas/usage-app-v3.schema.json)
- [Price request schema](../schemas/pricing-request-v1.schema.json) and [price response schema](../schemas/pricing-response-v1.schema.json), sourced from `core/src/pricing_sync.rs`
- `client/src/generated/usage-request.ts`, `usage-app.ts`, and validators

Run `corepack pnpm contracts:generate` to regenerate; `contracts:check` rejects drift. The portable client validates requests and responses and exposes no general shell, arbitrary file writes, or arbitrary dispatch.

`outputVersion=3` versions public results; `schemaVersion=3` versions internal snapshots. Source adapters and prices have separate versions. Core messages use `{op:"usage_app",args:Request}` → `{ok:true,value:Response}` or `{ok:false,error,code,details}`. Usage operations are refresh, usage, threads, turns, and steps. The separate `prices` interface provides status/update with `outputVersion=1`.

See [CLI](../guides/cli.en.md) for operations, enums, pagination, and errors. Measurement integers cannot exceed JavaScript's safe integer range; amounts remain decimal strings. New fields and rules require checking generated types, Web, JSON, and read-only compatibility with old snapshots together.

Usage requests add optional `presentation`, defaulting to details; distribution retains only period subtotals. With either explicit presentation, offset/limit/page.total count periods; a detail page includes every model row for those periods without splitting groups. Omitting presentation retains existing row pagination. The core computes both `sort: cost` and token ordering. Response `distribution` supplies complete-range maxima, tied peak dates and exact filter scopes, and unpriced token counts. Usage, turn, and measurement `costShare` uses the complete-range priced amount as denominator; unknown or zero denominators return missing values. Threads sort by matchedUsage or latest matching measurement; threadUsage retains full usage. Turns remain complete by default. Only turns accepts matchedOnly and locateTurnId, filtering and sorting before locating a page. Matching-only mode changes items/page, not the full-conversation summary or share denominator; steps remain complete.

## Client entries

`@wombat/client` exports generated types including `UsageRequest` and `UsageResult`, plus `UsageClient.query(request, { signal, onProgress })`. `UsageClient.prices({action:"status"|"update"}, {signal,onProgress})` returns generated `PricingResult` with the full catalog and version/source hashes. `UsageClient.live({query,mode,verify}, options)` is optional host functionality; Node supplies it and CLI uses it by default, while fixed snapshots use query. `createUsageClient(transport, pricingTransport, liveTransport, configTransport, optimizeTransport, preferencesTransport)` wraps narrow transports and validates the protocol. The portable entry contains neither Node nor React dependencies.

`@wombat/client/node` provides `createNodeClient({ binaryPath, timeoutMs, maxResponseBytes })` and owns local subprocess lifecycles. Callers do not handle arbitrary core operation strings. Other hosts can implement the same narrow transports and reuse generated contracts and validators.

Node's price transport downloads only the fixed official HTTPS document. The host request for the core `prices` operation includes document for update; status rejects it. Raw documents are absent from public request/response types. Rust parses and publishes them; other hosts must implement the same fixed-source retrieval flow.

## Read-only configuration contract v1

`core/src/config_dto.rs` generates [requests](../schemas/config-request-v1.schema.json) and [responses](../schemas/config-response-v1.schema.json). Node/HTTP supply `UsageClient.config`. list/detail/evidence/related_scopes/capabilities never write sources; capabilities does not scan. Omitted readView recollects configuration. Dates default to 30 days in UTC with an exclusive end; `scope.allTime` includes unknown dates and rejects simultaneous date bounds. Configuration scope has no model/effort attribution; current-content measurements are independent of dates.

A readView pins configuration metadata and usage references, retaining at most8 views globally for10 minutes. Eviction, expiry and restart return VIEW_EXPIRED. Valid configuration views extend service lifetime and retain original usage for returning to task turns. Subsequent roots/projectRoots must match the creating request; Web accepts only identities it published and injects startup roots.

Source roots inventory the exact filename AGENTS.md, top-level MCP in config.toml, skills and .agents/skills; default ~/.codex also reads ~/.agents/skills. Authorized projects boundedly discover AGENTS.md recursively and read .agents/skills and .codex/config.toml, excluding .git, node_modules, target, dist, .codex, .agents and symlink directories. Exact directory-entry names are checked even on case-insensitive filesystems. Discovery does not establish loading precedence or historical adoption. Scan limits are10 MiB per file,64 MiB total reads,10,000 inspected entries and new items each, depth8 and256 issues; limits report resourceLimited.

Complete UTF-8 files provide actual bytes, Unicode code points and content hashes; Skill measurements include front matter. `estimate` uses fixed ordinary encoding `tiktoken-rs-0.12.0/o200k_base/ordinary-v1`, recording complete-file payload, fingerprint and referenceEncodingOnly. It includes no chat wrapper and does not represent an unknown model. Estimates are limited to1 MiB per file and8 MiB per round; at most2,048 numeric counts are cached by method/hash without bodies. Empty content is zero; limits, invalid encoding, missing files and read failures remain distinct. Reliable metadata bytes declare filesystemMetadata and never pair with old content values; historical/stale measurements stay marked old. MCP lacks complete model-visible definitions, so characters and tokens remain unknown; services are not executed to obtain definitions.

Skill YAML parses name/description; description length comes only from a successful field. Headers are limited to64 KiB,10,000 events and depth32, without include resolution. Budget limits or unsupported extensions are not format failures. File reads are loading evidence only. AGENTS.md usage counts are absent; explicit Skill calls and MCP resource reads lack reliable adapters and cannot be replaced with read counts. Native MCP tool attempts with separate server identity count failed attempts and distinct retries, deduplicating the same operation; tool prefixes cannot identify an instance. Unobserved usageCount remains absent. Dates filter historical events; lastRecordAt is the last matching evidence.

Associated usage deduplicates matching measurements in reliably linked turns, without allocating exclusive configuration costs. Rows can overlap; summaries use a union. Missing links remain absent; full-turn usage is queried separately through the original usage view. Evidence queries still traverse safe facts; incremental association indexes, persistent composite views and cooperative cancellation are pending. Cancellation disconnects transport and isolates late responses; scans remain resource-bounded.

currentItems excludes explicitly missing paths while inventory still exposes missing rows. Explicit reads link by exact path evidence, even when cwd is nested under an authorized root.

Derived config-v1 atomic JSON stores safe metadata only, at most20,000 items per scope and16 MiB for old-cache reads. Configuration bodies, environment values, command arguments and tool outputs are not retained; scanning neither accesses the network nor executes MCP. Rebuildable metadata is separate from irreplaceable user review records.

## Optimize and preference contracts v1

`core/src/optimize_dto.rs` generates [requests](../schemas/optimize-request-v1.schema.json) and [responses](../schemas/optimize-response-v1.schema.json). Node/HTTP UsageClient.optimize supports list/detail/history(group), ignore/mark_edited/restore/recheck/capabilities; see the [CLI guide](../guides/cli.en.md). Object rules follow this page’s threshold revision. Dates/models do not affect checks; check time is independent. Project/source/category, pending/history and up to200-item pagination are supported, default50.

Suggestion identity binds source, object, content fingerprint, findings and project scope. readView pins facts; decisionRevision pins user records, with conflicts returning VIEW_EXPIRED. Acknowledged same-state ignore/mark_edited retries do not append duplicates; restore applies only to the latest ignored record. recheck validates old authorization before recollection, returning awaitingRecheck, stillNeedsReview, verified or recheckUnavailable. verified establishes only observable static checks, not adoption or savings. History entries retain separate recordId values.

User records live in `user-v1/reviews.sqlite3`, with independent transactions and20,000-record limits that error rather than delete history. Rebuilding inventory retains decisions. Inactivity, MCP faults, space cleanup, previews, execution and recovery capabilities are explicitly false and results partial. There is no arbitrary file writing, shell or dispatch.

`core/src/preferences.rs` generates [preference requests](../schemas/preferences-request-v1.schema.json) and [responses](../schemas/preferences-response-v1.schema.json). `UsageClient.preferences` only gets/sets zh/en in private atomic `user-v1/language.json`, accepting no arbitrary paths/content. See the [language contract](../i18n/product.en.md) for Web priority.

Current rules use static-config-v4. bodyTokenEstimate independently encodes the exact body, payload=skillBody, with tokenizerVersion, method/contentHash and referenceEncodingOnly; containing configRevision/readView pins the snapshot. bodyEstimateStatus exposes unknown/parsing/resource gaps; old caches default to unknown and failed parsing never becomes zero. Full file/body each have a1MiB limit; both inputs count toward the8MiB round budget. AGENTS.md>16,384B is a product reminder, Skill body≥5,000 a reference reminder, description501–1,024 a product reminder and >1,024 a specification issue without duplicate500 reminders. ruleOverrides accepts only positive safe-integer agentsBytes and descriptionCharacters0..1024; ruleParameters returns defaults/overrides/fixed lines and authorized-current-config applicability. Records retain original rules and recheckRuleParameters records recheck rules. Specification constraints are immutable; unknown bodies cannot pass recheck. Loading-budget/inactivity/storage capabilities remain closed; see the [upgrade specification](../project/config-upgrade.en.md).

mark_edited additionally saves reviewBaseline: safe measured metadata at the marked version, never source bodies. Recheck retains that original baseline while updating item; missing baselines in old records default to null, and recheckRuleParameters identifies the recheck separately. Byte/codepoint comparisons require complete non-stale measurements on both sides; body tokens additionally require available estimates and identical method, encoding, payload and tokenizer version. Only before/after text measurements are shown; neither threshold differences nor related usage are savings. Web related usage reuses config evidence and its usageRevision, keeping dates outside optimize rule identity. CLI/Agent use inventory evidence and turns for the same facts.

static-config-v4 adds exact-block and declared-copy evidence: file versions, raw byte/line positions, declaration hashes, direction, and transform, without bodies; see the [specification](../project/startup-rules.en.md) for declarations and limits. Config capabilities may return startup-authorized roots and a copyable host restart command; these are not successful-scan facts or an execution API. live freshness.errorCode exposes storage/migration errors. facets.discoveredThreadCount counts discovered task metadata in the snapshot, independently of date-filtered measurements.

Declared evidence in static-config-v4 binds source instance, authorized project, declaration path/hash, relation ID and kind. A relation is complete only when every member is complete and applicability is confirmed. Unknown headings/reference bases, absent declarations and limited members yield recheckUnavailable; legacy declaration evidence without relation identity remains readable but cannot pass. Identical declaration text cannot substitute for another project’s declaration.

Current configuration aggregates local physical objects by canonical path, kind and native key; shared projects are collected once. authorizedProjects retains overlapping root memberships and project is presentation attribution. sourceContexts retains legacy source inventory identities, source/version and per-source observations; the compatible sourceInstanceId field is not the complete source list. Source filtering counts matching events only; associated tokens/costs still use the original ledger union. One current object produces one suggestion, with consistent handling across matching sources; declaration evidence stays source-specific. Legacy identities authorize old caches/reviews without merging ledger identities. Versions changing between reads expose configContentChangedDuringScan and retain separate entries.

reviews.sqlite3 independently uses user_version=1: review_events stores each state event and review_parts shares safe evidence, item and original baseline; SQLite JSONB is internal only. Authorization/project/category COUNT and LIMIT/OFFSET precede page decoding. State queries scan lightweight metadata; rechecks select the latest record per physical object. Legacy decisions migrate row by row in one transaction, preserving sequence/identity/evidence; bad rows roll back and unknown versions are refused. One VACUUM follows commit; user history is never automatically cleared. A4MiB page cache,512-page checkpoint and8MiB retained-WAL target are not hard limits. Migration and regular paging are measured separately; see the [decision](../decisions/implemented/architecture/2026-10-02-rule-review-integrity.en.md).
