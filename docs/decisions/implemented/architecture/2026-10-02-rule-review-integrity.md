# 决策记录：物理配置身份、完整复查与共享处理记录

中文 | [English](2026-10-02-rule-review-integrity.en.md)

Status: implemented

## 问题

声明内容相同不能证明它来自同一个项目。读取完成也不意味着标题或相对引用的适用条件已确认，复查不能把未知当修复。重叠授权目录和多个日志来源会盘点同一个本机文件；来源身份既要保留，也不能让同一文件出现多条需要分别忽略的建议。完整依据逐次复制进用户历史、分页前全库解码，造成随历史增长的磁盘与内存开销。

## 决定

规则使用static-config-v4。每条声明关系绑定来源实例、授权项目、声明路径与哈希、关系ID和种类，单独保存Complete/Unknown及成员集合。只在适用条件和所有成员都完整时允许旧关系依据复查；旧证据缺关系身份则保持不可用。声明失效、标题/相对引用未知、成员或输出资源缺口不能判通过。精确原文、位置和各来源声明依据继续独立，不推断实际加载。

当前本机配置按规范路径、种类与原生键聚合，保存所有来源盘点身份和重叠授权成员；兼容单一来源字段只用于展示。共享项目文件只采集一次，同来源全局/项目作用范围仍分开验证。每个当前物理对象只有一条建议，忽略/恢复/标记/复查统一作用于该对象。事件及账本仍按来源独立，相关用量取集合并集，不因文件聚合或重复读取减少账本。版本在不同采集间变化时保留分项并公开缺口；旧缓存和用户记录通过原来源身份继续授权读取。

独立用户数据库升级user_version=1。不可变安全依据、item及原始baseline存入共享review_parts，逐次状态和记录身份存入review_events，内部用JSONB。哈希选候选后比较完整JSON，避免碰撞误共享。最新状态查询仅读轻量元数据，授权对象及项目/类别过滤与分页先在SQLite执行，复查按物理对象选择最新事件。旧decisions逐行事务迁移，序号/身份/原始依据保留；失败整批回滚，未知版本拒绝，提交后一次压实。用户历史不因索引重建或自动空间清理删除。

## 考虑过的方案

单用声明哈希仍会跨项目误认；单用文件读取完成性仍会把未知条件当通过。直接删除来源维度会破坏事件归属，因此把物理对象与逐来源事实分层。继续复制完整Suggestion并在内存分页保留了简单布局，但复查重复依据和分页内存随记录数增长；改为共享事实与数据库分页。没有引入另一套费用分摊或自动配置写入。

## 影响与验证

保留输出v1，Rust生成新增兼容字段。旧规则和记录可读，未提供新关系身份的旧声明证据不能自动判通过；旧忽略不能隐藏新规则。记录上限20,000，页缓存目标4MiB、512页检查点及WAL保留目标8MiB，不是全进程或磁盘硬上限。索引查询仍需扫描轻量历史元数据；共享程度取决于真实依据重复度，迁移包含事务和压实成本。

合成回归覆盖条件未知、相同声明跨项目、关系成员不足、重叠授权、双来源共享文件与独立同ID账本、完整处理闭环、旧记录身份/基线、坏迁移回滚、未来版本及仅解码所请求页面。CLI/Web按固定版本一致。实际运行、测量条件和未验证平台见[进度](../../../project/progress.md)及[契约](../../../development/contracts.md)；不以此开放Hook、真实注入、执行或撤销。
