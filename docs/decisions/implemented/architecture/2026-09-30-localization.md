# 决策记录：共享展示语言与章节级文档配对

中文 | [English](2026-09-30-localization.en.md)

Status: implemented

## 问题

CLI/TUI 的中文文字分散在展示函数中，部分交互从按钮文字推断操作。文档使用整篇哈希，无法直接定位失去同步的章节，并容易让独立修改冲突。

## 决定

借鉴 DeepSeek Harness 的语言服务、文案归属检查与章节级配对设计，Wombat 使用 `@wombat/client/locale` 纯展示入口，完整中英消息字典、类型化参数、不可变语言状态和订阅。操作标识独立于文字，模块级标签延迟读取；语言不进入 Rust 业务协议。

文档使用 Markdown 语法树比较结构，以英文标题路径记录章节哈希。保留既有中文路径、JSON 记录与显式未配对清单；旧记录仅在原哈希匹配时迁移。人工审校仍负责语义，哈希只是确认记录。

## 考虑过的方案

- 整体移入上游插件语言系统：它服务浏览器、宿主设置和动态语言插件，Wombat 当前 CLI/TUI 不需要这些依赖。
- 继续整篇哈希与正则检查：实现更少，但无法准确比较嵌套列表、表格及章节变化。
- 同时增加持久偏好与任意语言包：本轮保留命令参数、环境变量和会话切换，避免扩大配置写入与插件生命周期范围。

## 影响与验证

参数、错误码、Token、金额、模型名称与来源正文保持原值。未知内核诊断仍可能是中文，未宣称全协议文本翻译；使用说明与边界见[产品语言](../../../i18n/product.md)。

验证覆盖章节变更定位、代码块一致性、嵌套列表、表格、链接、字典参数，以及运行时语言切换、原生终端与原始标题保留。完整构建和行为验证仍按仓库验证规则执行，测试数量不代表全部平台或视觉验收。
