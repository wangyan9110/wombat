# 决策记录：只读配置与复合读取版本

中文 | [English](2026-10-01-config-inventory.en.md)

Status: implemented

## 问题

配置文件描述当前状态，日志只提供部分历史证据。混合两者可能把当前内容当作历史版本，或把同一轮次重复计算成配置独占费用。界面和 CLI 需要同口径查询及可靠往返。

## 决定

Rust 拥有配置采集、关联和证据图，Web/CLI 并列消费生成契约，不通过统一 CLI 中转。配置授权与来源扫描范围分开，当前项目发现与授权见[项目发现决定](2026-10-04-observed-project-discovery.md)。可靠文件读取、原生服务身份和明确事件分别保留；工具前缀不认定唯一配置实例。

复合读取版本固定安全配置元数据与用量引用，使普通用量版本淘汰后仍可在保留期返回原轮次。过期或服务重启明确失败，不能静默切换版本。当前格式、保留期和资源限制归属[配置契约](../../../development/contracts.md)。

采用有界内存版本与原子 JSON 元数据缓存，不为未交付能力预建数据库表。最近成功元数据可以区分历史条目和读取失败，但不证明历史正文或加载。测量方法与独立用户记录的理由见[测量决定](2026-10-02-config-reviews.md)。

## 考虑过的方案

类型化 SQLite 配置/关联表、持久复合版本和增量依赖索引可以减少安全事实遍历，但需要版本一致性、失效、部分失败与清理设计，不能只替换存储格式。本次保留简单有界实现；只有实际查询成本证明必要时才实施这条候选路线，不重写用量账本或把索引放到 UI/Node。

统一 CLI 中转会把产品能力绑定到命令装配，故各宿主直接消费共享契约。当前文件套用历史记录或按轮次直接累加关联费用更简单，却无法提供历史真值或守恒；关联用量须按范围内明确计量身份取并集。

## 影响与验证

配置查询不改来源、不启动 MCP 或联网探测，不保存正文、命令参数或环境值。传输取消隔离迟到结果；协作取消、持久复合版本和增量关联索引仍需独立实现及验收，不把这些候选方案标为已实施。

现有合成测试覆盖越权软链、循环、无执行、敏感值隔离、资源边界和版本淘汰；Web/CLI 端到端覆盖关联守恒、分页、版本变化和读取失败。实际产品缺口统一见[未完成提案](../../proposed/product/2026-10-03-optimization-lifecycle.md)。

原配置分析提案的规模目标继续作为待验收条件：固定 100,000 条计量、100,000 次操作、10,000 项配置与 100,000 条关联边；分别报告冷/热缓存、分段耗时、p50/p95、进程内存和结果一致性。热查询 p95 ≤300ms 是目标，既有稳定链路回退超过10%须调查，不是已测得的保证。持久版本、增量更新、取消和资源超限均须真实组装入口及故障测试，不能以接口样例代替。
