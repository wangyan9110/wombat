# Decision: local Web and a shared frontend

[中文](2026-10-01-local-web.md) | English

Status: implemented

## Problem

Web, CLI, and future desktop hosts need shared Rust business logic without reimplementing accounting in the browser or exposing generic core dispatch. Desktop selection must also fit the existing Rust/TypeScript engineering and distribution costs.

## Decision

The React frontend consumes narrow operations through generated contracts and UsageClient. The local Node host reuses core process management, connections, and official-price downloads. Future Tauri 2 injects a restricted transport while Rust retains business logic. The [Web README](../../../../web/README.en.md) owns current host authentication, limits, and lifecycle; the [UI README](../../../../ui/README.en.md) owns frontend boundaries.

Tauri 2 reuses the system WebView and Rust, avoiding a separate desktop business implementation or bundled Chromium. This is an engineering and distribution tradeoff, not measured proof of lower memory or faster startup. The desktop project is not delivered; shipping Web first does not change the desktop choice. Subsequent [TUI removal](2026-10-01-remove-tui.en.md) ended the transitional terminal arrangement.

## Alternatives considered

A Rust HTTP host could reduce runtime layers but would require migrating existing Node connection, process, and restricted-download logic; reconsider only with benefits that justify that cost. Desktop-only delivery would not meet the need to ship Web first.

Electron provides consistent Chromium/Node rendering but increases distribution and runtime maintenance. A native Rust GUI reduces Web dependencies but cannot directly reuse React pages. Both could retain the shared core; Tauri is the selected route.

## Consequences and verification

Web assets ship with the CLI; [distribution](../../../reference/distribution.en.md) owns runtime requirements. A local startup token is not a remote account system. Sources remain read-only and unsupported rules remain unavailable.

Existing synthetic host tests cover authentication, file boundaries, resource limits, and cancellation; Rust end-to-end tests compare Web/CLI queries and drill-downs. Historical tests do not establish acceptance of the current build, Tauri, or every platform. [Unfinished proposal](../../proposed/product/2026-10-03-optimization-lifecycle.en.md) owns outstanding acceptance.

Desktop integration still needs a restricted sidecar-versus-library choice and evidence for cancellation, crashes, reconnects, single-writer coordination, and large-response backpressure, without arbitrary shell access. Target systems need installation/update signatures, IME, fonts, DPI, accessibility, and sleep recovery checks, plus separate process-tree startup, idle CPU, memory, package-size, and long-running measurements. Unknown protocol or data versions follow the [current-format decision](2026-10-03-current-format-only.en.md): reject and preserve data. Desktop updates and official-price updates have different trust boundaries.
