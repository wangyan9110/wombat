# 决策记录：缺价触发官方价格检查

中文 | [English](2026-09-30-automatic-prices.en.md)

Status: implemented

## 问题

内置价表可能没有新模型；手动更新要求用户先发现缺价。实时列表又会频繁查询，逐次下载会放大网络请求并拖慢查询。

## 决定

Rust 在计价结果中标记可补齐的缺价：明确的 OpenAI 模型、有效且非零的用量、缺少适用单价。Node 实时客户端复用固定官方文档下载和 Rust 校验；不发送模型列表、日志或账户凭据。成功后按原筛选重读一次，固定快照和缓存查询不触发；环境变量可关闭自动联网。

Rust 在产品数据目录持久保存尝试状态，以文件锁及60秒租约合并跨进程下载；失败冷却15分钟，成功检查冷却24小时。宿主自动下载最多5秒，解析/提交有独立超时；进程中缓存冷却回执，避免终端每秒启动检查进程。失败返回现有用量及独立价格状态，不伪装成已计价。手动更新仍可立即重试。

## 考虑过的方案

仅手动更新不能满足用户要求。每次缺价查询都下载会重复请求官方页面。永久定时服务增加生命周期和空闲资源开销，因此采用查询触发、持久冷却和短租约。未知模型名或请求条件不是价表能修复的证据缺口，不能因此反复下载或借价。

## 影响与验证

用户已要求缺价自动拉取，默认实时查询因此可能联网；原日志仍只读，无 API Key。只导入现有解析器能验证的标准价格，页面变更或拒绝访问时保留旧价表。公开 `priceUpdate` 与日志新鲜度分开；未定价仍不同于零。跨进程限流、租约过期、失败保留、独立金额、旧快照及终端路径通过合成样本验证；实际结果见 Git 历史中的验证记录，操作和限制见[价格口径](../../../reference/pricing.md)。
