# 决策记录：任务统计与宿主驱动监控

中文 | [English](2026-10-09-task-statistics-monitoring.en.md)

Status: implemented

## 问题

判断任务是否异常大、解释用量增长或检测用户预算阈值，需要在同一账本和范围上执行可重复统计。在对话中重建这些事实会重复工作，并可能混用总体。用户要求同时提供这些能力、持续预算检查和周期复盘。

## 决定

Rust 拥有任务总体统计和描述性变化比较。宿主通过同一公共客户端消费生成结果。用户预算与确认状态位于可重建索引之外。CLI watch 和明确启用的 Web 循环在各自生命周期内驱动检查。

此决策仅部分替代[优化生命周期提案](../../proposed/product/2026-10-03-optimization-lifecycle.md) G13 对持续监控的排除。一次查询复盘及证据区分继续适用。宿主驱动检查不安装后台调度器。G05 连续闲置和完整 G08 采用要求仍是提案：有界的未记录使用区间和受支持的原生版本匹配提供有用证据，但不完成这些要求。

## 考虑过的方案

对话侧计算没有可复用的持久统计契约，可能混用范围或分页。共享 Rust 查询提供确定的总体，由 Codex 解释结果。专用后台服务增加安装与生命周期责任；明确运行的宿主满足当前本地监控需求，并使运行期限可见。

## 影响与验证

监控需要运行中的宿主和新记录的用量。提醒绑定授权来源集合，避免某个受限宿主占用另一宿主的阈值提醒。迟到数据改变复盘事实时可以产生新版本；确认状态保持独立。读取或加载的内容匹配、等长的变更前后窗口，不能证明行为采用或因果节省。

[核心参考](../../../reference/core.md)拥有方法和限制；[CLI 指南](../../../guides/cli.md)拥有用户操作。独立合成测试覆盖分位数、增长贡献对账、不完整总体、持久去重与确认、生成契约，以及限制来源的 CLI/Web 交付。实时基准同时将任务分布与夹具真值比较；它不证明任意历史调查的性能。
