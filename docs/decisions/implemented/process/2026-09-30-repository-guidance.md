# 决策记录：仓库规则与双语确认

中文 | [English](2026-09-30-repository-guidance.en.md)

Status: implemented

## 问题

仓库原有规则集中在根文件，模块、文档和 Skill 的职责容易互相重述；中文文档和英文入口修改时也缺少同步证据。完整移植大型仓库的治理系统会增加当前项目不需要的维护成本。

## 决定

保留根文件的全仓规则，在实际模块、文档和 Skill 目录补充局部约定；各模块 README 说明公开入口。公开页面按各自目录配对英文，并用指定文件的确认记录与静态检查阻止无意失配。持久的设计理由用本目录记录，日常验证仍按改动范围选择。

各级 AGENTS.md 使用英文，根文件按任务导航，不要求全量读取历史。参考 [DeepSeek Harness 文档分层](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/AGENTS.md)，每项事实只维护一处；取消路线图、支持矩阵和滚动进度文档，能力归属模块说明或技术参考，未完成验收保留在实施状态，验证结果保留在任务、PR、CI 或专门测量材料中。旧验证记录可从 Git 历史追溯，不复制为新的汇总台账。

源码规则检查在 CI 独立作业中先于平台构建执行。篇幅、Skill 元数据和决策格式检查用隔离的有效样本及违规反例验证；英文转换按非空白字符计数调整子目录篇幅上限，根文件上限保持不变。

## 考虑过的方案

- **只保留根文件**：规则与模块细节继续混在每次会话的基础上下文中，文档和 Skill 缺少就近归属。
- **继续维护多份状态汇总**：一次功能变化需要同步多个页面，易产生矛盾和额外的 AI 上下文；已有事实归属与验收状态足以支撑当前开发。

## 影响与验证

新增目录约定、双语配对和聚焦脚本；原有中文页面已按用途整理并补齐双语，配对清单不再有旧文档待迁移项。`repo:check` 检查规则、配对与公开引用，但不证明译文语义、产品行为或终端视觉；这些仍需人工审校及相应测试。
