## 升级范围与交付原则

本次是跨 core、client、cli、web、ui 的较大升级，涉及事件事实、索引/快照格式、计量投影、规则结果和页面交互；不是只增加耗时面板。首期包含 Codex 安全事件、固定证据视图、现有计量守恒、Skill/MCP 使用次数、耗时指标、规则适配及 CLI/Web 同口径交付。保留现有模块化单体，不新增服务或通用规则引擎。

compare、watch 扩展、语义分类、长期闲置/重复注入/连接故障新规则、其他 Agent 和 Tauri 不属于本次任务。账户与价表保留现有职责，按需引用版本，不为统一日志重写所有业务。未知历史信息保持未知，当前配置不能补成历史配置。原始日志只读，索引可重建，用户决定和复查基线独立保护。

以一个任务为默认审阅单元；涉及格式切换的紧密依赖可作为一个集成批次，批次内按职责分提交。每个集成节点须保持可构建和已有入口可用。开发期间可用合成数据进行新旧结果对照，但产品不保留双账本、旧格式兼容读取或自动迁移。实现状态只有在对应证据齐全后才更新。

2026-10-04 用户调整：中间批次只运行新增或受影响模块的独立测试；集成、端到端和完整回归统一放到最后一批 U19。原型基于已有内部设计，在内部工作区维护；公开规格不依赖私有文件。在此调整前已完成的基线集成属于历史证据，不代表后续中间阶段继续执行。

## 执行顺序与里程碑

推荐起步顺序为 U01 → U02，然后启动 U03 原型和 U04 事件适配。U10、U11 可基于稳定契约与合成数据独立推进；U06/U07 是固定版本查询的关键依赖。U14 的耗时/使用接口可先验收，规则接口等 U12/U13；同一契约文件的修改需统一集成，不能把“可并行”解释为无约束同时编辑。这里只描述任务依赖，不表示已启动并行代理或创建工作分支。

| 节点 | 必须具备 | 对用户的意义 |
|---|---|---|
| M0 设计可执行 | U01—U03 | 数据契约有真值，页面能走查，存储和历史保护方案明确 |
| M1 数据基础可靠 | U04—U08 | 持续变化日志可正确采集，现有用量守恒，固定版本可重建 |
| M2 指标与规则正确 | U09—U13 | 次数、耗时和规则都有依据，用户决定及复查边界保持 |
| M3 模块就绪 | U14—U18 | 各入口实现与模块独立测试完成，整体集成待最终验收 |
| M4 升级交付 | U19—U20 | 资源成本可核对，文档与验收边界完整 |

原型与静态规则重构可以提前完成，但不能因此跳过事件存储和账本一致性门禁。U18 汇总模块独立证据，U19 仅在最后一批补跨模块验证；也不机械重跑与后续改动无关的验证。

## 风险与完成记录

优先审查三个风险：事件替换造成重复或漏记账本；历史使用与当前配置错误关联；存储/身份变更影响用户决定。U02 必须给出可验证保护办法，未确定前不执行格式切换。来源不足的能力按缺口交付，不通过新增未经授权采集来补齐。

每项关闭时记录改动范围、提交/PR、实际验证命令与结果、语料/构建版本和未完成边界；合成材料可公开，真实日志自测仅存仓库外。文档任务执行 repo:check 和差异检查；Rust 与跨语言任务遵循仓库相应门禁；依赖变化补许可审查。平台、浏览器、性能和安装分别验收，未验证项不得默认为通过。整体工作量在 U01/U02 明确字段和存储影响后再估算，不先承诺工期。

## 第一批记录与冻结契约 · 2026-10-04

设计及清单已由 411bd53 提交并推送。[基线证据](../benchmarks/2026-10-04-event-upgrade-baseline.json)记录固定源码、合成语料指纹、账本真值与实际检查。基线 build、Rust 183 项、模块测试、集成和端到端通过；初次受沙箱临时 socket 权限限制，获准本机执行后通过。集成发生在用户调整之前，后续直到 U19 只做增量模块独立测试。

U02 冻结以下实施约束；它们是下一批实现契约，不代表存储已经升版：

- 事件键由来源身份、文件代次、完整记录的字节偏移及该记录内的类型化事实序号组成。追加保持代次；截断或已读前缀变化进入新代次，替换该来源旧贡献。路径和会话身份不互相代替。
- 操作键优先采用来源、可靠会话/轮次及原生调用身份，开始、结果和流式更新引用同一键。无原生身份时保留事件级候选；不按名称、时间邻近或相同输出强行合并。可靠分叉继承由既有账本去重规则处理，独立调用不合并。
- 每次提交固定各来源代次、完整行结束偏移和解析/投影版本；未完成尾行不推进水位。事件、游标和投影同事务提交，取消和失败不得发布半版本。各文件水位不是全目录同一时刻的证明。
- 发生时间、观察时间、原生时长及精度分别保存；缺值保持未知。规则输入绑定配置内容版本、事件投影版本、宿主观察作用域/时刻、方法版本、参数与计算截止时间；只使相关依赖失效。
- 下一格式采用设计第 14 节的 rollout-6、live-v2/DB4、usage-v4/schema4、protocol2。旧索引目录和显式旧快照保留并拒绝混读。user-v1/reviews.sqlite3 独立保留，重建流程不打开其写事务、不清空决定/理由/基线；格式切换后的保留检查放在最终集成。

U03 基于现有内部原型增量修改，保留导航、任务摘要、项目与账户结构。执行过程、操作依据、使用次数、分享和五类规则检查嵌入现有页面；中英文、宽窄屏、四种场景共 20 组新增模块检查通过，完成截图走查和字段映射。原型为合成演示，公开构建不依赖内部文件，不作为产品接口验收。U01—U03 关闭；产品功能、性能、平台和最终集成尚未完成。

## 事件基础实施 · 2026-10-04

来源事件首个持久化增量：已从一次解析中保留轮次开始/完成/取消/失败、原生耗时/首 Token 耗时及上下文窗口变化；无效原生数值保持未知并报告缺口。事件与游标同事务保存，实时投影引用解析事实，固定快照单独保存有校验的事件文件，轮次分片不重复写入事件。追加/重启保留代次，已检测到的截断或物理替换换代；全量复验保留未变化文件身份，来源消失保留历史事实。
