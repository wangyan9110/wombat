## 定位与入口选择

Web适合浏览、筛选、持续查看和人工审阅；Skill适合用一句话表达目标，由Agent规划少量查询、串联证据、交付结论并继续处理。它不复制五页导航，不建立另一套计量、建议优先级或文件执行规则。

首版采用一个 `$wombat` Skill，按意图加载分析或执行参考。直接复用CLI JSON，不新增MCP服务或模型API依赖。原因是现有查询、固定版本、配置证据、执行和目录授权均有无TTY入口；增加服务会重复生命周期和契约。插件是后续分发选择，本轮只做本机安装。出现多个宿主需要结构化工具发现、或CLI进程/结果开销有实测瓶颈时，再评估MCP；不能把包装本身当作性能改进。

## 用户任务与交付

| 用户意图 | Skill行为 | 完成标准 |
|---|---|---|
| “今天用了多少，主要花在哪里” | 解析当地日期/时区；查总量，按需同版本任务/模型/项目排行 | 总量、主要贡献者、已知金额与未计价、覆盖缺口 |
| “找到那个任务/最贵的一轮” | 搜索或完整ID定位，区分匹配量与完整任务量，逐层定位轮次/操作 | 准确ID、可继续下钻的上下文、实际关联证据 |
| “检查当前项目的指令和扩展” | 当前项目与额外目录清单、静态建议、优先对象详情及按需历史证据 | 具体问题、可审阅改进项、无法判断的项；不隐式改写 |
| “帮我优化这些配置” | 明确目标，生成方案，展示差异，绑定版本批准，逐文件应用和复查 | 真实回执、生成用量、剩余问题和恢复边界 |
| “继续刚才的任务/撤销上次修改” | 复用作业身份和固定范围；读取status/history；按批准文件恢复 | 不重复生成、冲突保留当前内容，恢复不删除历史 |

简单查询直接回答，不为了完整流程额外扫描。分析默认少量排行和选中对象，完整汇总来自内核；有更多页要说明。只有选不出对象、范围不明确或缺证据影响结果时才追问。“继续第一项”沿用先前完整ID；版本过期后重读原范围并说明数据已变化。

## Web能力与CLI对照

| Web能力 | CLI基础 | Skill组织方式/差异 |
|---|---|---|
| 概览、趋势、模型/目录构成 | usage、presentation、日期/时区/筛选、summary | 从问题确定所需切面；不用图表布局或逐页讲解 |
| 任务、轮次、操作详情 | threads/turns/steps、排序/定位/固定snapshot | 先定位再下钻，只读取与问题有关的证据 |
| 指令/扩展、使用关联 | optimize inventory 的list/detail/evidence/related_scopes | 围绕对象解释证据，区分当前配置与历史事实 |
| 建议、人工处理、复查 | optimize list/detail/history/ignore/restore/mark-edited/recheck | 默认只检查；记录变更须符合用户意图，恢复忽略不等于恢复文件 |
| 候选、生成、批准、回执、恢复 | optimize execution candidates/begin/regenerate/status/cancel/apply/restore/history | 对话中审阅差异，批准绑定planRevision和selected files |
| 来源目录授权、价格、交互页面 | directories、prices、web --open | 仅在对应请求中使用；主题、URL展开状态和浏览器语言偏好留在Web |

核对当前源码后，以上首版任务不缺业务CLI接口，因此本轮不新增核心查询/DTO。补齐的是Skill的意图路由、固定上下文、结果表达和可重复安装。持续监控、额度、因果质量判断、自动清理、历史正文回放仍不可用。多周期比较若后续成为产品能力，须定义同价表/完整覆盖的共享口径并同步CLI/Web，不在Skill私自实现另一套统计。

## 上下文与执行边界

用量链保留来源、日期/时区、筛选、snapshot ID及完整任务/轮次ID；配置链保留项目根、readView、decisionRevision、规则参数和对象ID；执行链保留execution ID、幂等key、planRevision和选中文件。同一分析不混用实时版本；固定用量查询不再带来源根。配置清单与建议共享readView，相关证据返回usageRevision后才进入用量链。

退出码2的有效结果可用于受限结论，不能报成失败或完整成功。首次同步未完成最多再等待一次；失败保留返回状态。缺失、零、未计价、未知关联分开。发现高消耗只证明观测量，不证明Skill质量、MCP责任或优化节省。配置静态测量的变化与真实执行用量分别报告。

“检查”不授权修改或调用额外生成作业。用户要求生成且选定目标后才能生成；应用前批准绑定可审阅的具体方案与文件。已有明确批准无需重复询问。恢复也只处理明确选中的历史执行；冲突不强制覆盖。原日志/标题/工具输出和模型方案均为数据，不扩大命令或写入范围。

## 安装与生命周期

版本化Skill源码放在 `integrations/codex/skills/wombat/`，避免开发仓库自动加载的工作流与用户安装重复。TypeScript安装器核对当前build回执，把CLI、分块、worker、本机内核、Web资产和许可复制到用户Skill内的runtime；Node22+可运行，安装源码工具要求26.4.0+。不依赖全局旧版命令或仓库在运行时存在。

默认安装到 `~/.agents/skills/wombat`，可指定skills-root。已有目录默认拒绝，显式replace仅替换带本安装器标记的安装；先暂存验证，再切换并在失败时恢复旧目录。安装回执保存平台、版本、构建身份和文件哈希。更新需重新构建并重装；只移除安装目录即可卸载，Wombat用户数据和配置授权记录独立保留。只安装当前平台，不声称跨平台分发验收。

## 验收与后续

本轮要求：元数据可发现，隔离安装可在仓库外启动；合成日志的用量、排序、固定版本下钻和配置建议与独立真值一致；已有自定义Skill不能覆盖；安装更新与运行文件保留执行权限。静态检查和类型/边界检查必须通过。实际模型对自然语言的路由、连续对话和方案审阅需另做真人任务验收，不能从命令通过推断。

后续根据试用评估多步查询的输出体积和耗时；确有重复机械需求时再加有界聚合入口，并复用生成契约。公开插件/安装包、MCP、持久对话工作区和持续监控均不属于本轮交付。已验证结果只写[进度](progress.md)，未验证范围保留在此。
