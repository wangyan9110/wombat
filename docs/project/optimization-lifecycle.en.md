## Surfaces and shared facts

Overview, Tasks, Instructions, Extensions and Optimize share sources, projects, dates and the usage ledger. Overview shows tokens, estimated API cost, account allowances, trends, distributions and recent tasks. Instructions form an AGENTS.md tree by user, project and subdirectory; Extensions list Skills, MCP and Hooks. Each preserves its own search, ordering and recommendation filters.

Task total, matched usage and selected turn remain separate. Recent turns follow reliable record times, never the highest ordinal. Pages do not replay full conversation bodies. Returning across pages restores scope, filters, turns, list and reading positions; refresh, language changes and late responses cannot replace a new selection. Dates include both endpoints; all dates includes undated records. Current files and account allowances are independent of historical dates.

Current configuration identity, historical working directories, and extra-directory sources remain separate. A reliable historical project can be selected to read current configuration directly without proving historical loading. Shared files are collected once; path similarity does not assign unknown tasks. Total tokens are input plus output; cache and reasoning are respective subitems. Costs use original precision per record, retaining unpriced tokens and unknown amounts. Related usage uses a union of reliable measurement identities, without allocating exclusive costs or predicting savings.

## Rules and resources

Complete AGENTS.md UTF-8 text above 16,384 B prompts review, with equality excluded; absence is a fact and creation is optional. Skill bodies exclude YAML and require valid parsing and a known method before a reminder at 5,000 estimated tokens or more. Description reminders cover 501–1,024 Unicode code points; above 1,024 is a separate applicable specification issue. Invalid YAML cannot provide a certain body result.

Exact blocks require original text, complete boundaries and a confirmed applicability chain or context. Duplicate injection requires a real request, context, generation, source version and actual inclusion positions. Replays are removed; parent/child tasks and compaction generations are separate. Copy drift requires declared relationships, both versions, transforms and direction; customizations cannot be overwritten automatically. Hook references require trusted effective enabled registration without executing scripts. Dynamic paths and denied access are not missing targets.

Skill/MCP inactivity requires stable identity, continuous enablement, at least 30 days of complete observable coverage and no usage, including failed attempts. Worktrees, caches and temporary resources require at least 14 days of complete observation and inactivity, ended tasks, no running tasks and no protection. Caches also need trustworthy ownership and regenerability; worktrees need modification, commit and recovery evidence. Directory times and zero usage under display filters cannot replace these facts. Recoverable relocation does not establish released space.

Versioned initial rapid-check parameters require at least five consecutive checks of one running task, intervals no longer than two seconds, no new output and no input or timely-response requirement. Aggregate recommendations additionally require at least five analyzable tasks, three hit tasks, two hit dates and a hit in the seven days before the observation endpoint. Necessary keepalive, interaction, long waits and evidence gaps are excluded; without a changeable location, only evidence is shown.

Usage counts come from explicit Skill invocation, MCP tool/resource/prompt actions and reliable Hook execution events. Reading SKILL.md, listing, loading and connecting are not invocations. Independent failures/retries count separately; stable replay identities deduplicate. Complete coverage without events is zero; incomplete coverage with events is an observed count, and absent evidence is unknown. AGENTS.md shows reads only.

## Handoff and handling

Single-item confirmation binds the current recommendation, object and project. Closing an unsent batch ends its selection; a later single item does not reuse it. Batch candidates cover all eligible recommendations in the current project, independent of page or type. Defaults include currently pending items; historical sends are not searched and task associations are not stored to exclude duplicates. Shared objects deduplicate, same-file rules merge, and project working directories stay distinct.

Send only necessary targets, working directories, rules, evidence/versions, handling direction, preservation conditions and access boundaries. Do not include complete history or private files by default. Explain that handling consumes tokens before sending; selecting all does not authorize arbitrary deletion.

Check that Codex accepted the request before showing successful delivery; execution receipts are not maintained in Wombat. Rechecks determine whether the problem remains. Duplicate clicks are suppressed while sending, without cross-process locks or historical deduplication. Explicit failure retains recommendations; unknown acknowledgment requires inspection in Codex; users may review and resend manually, without automatic resend. Use supported local paths, never developer chat coordination tools or fixed sample results as product APIs. Closing Wombat does not cancel sent tasks. Codex owns review, execution and restoration.

## Decisions and rechecks

Check facts and user decisions are independent; accepting a handoff request does not change either. Keep/not-applicable decisions record the problem instance, reason and actual time. New instances require separate review; rebuilding indexes retains decisions. Redisplay only changes presentation, never files. Refresh does not recreate handling times, and sent does not mean resolved.

Single/global rechecks share rules, inspect only authorized scope and never start inference. Dependencies are independent: historical gaps do not block readable file size, format or reference checks. Passing problems enter history, remaining problems stay pending, and unavailable checks retain original recommendations and prior results. Missing files do not pass automatically. Rechecks do not revoke user decisions.

Static outcomes and natural follow-up adoption stay separate: no new records, unknown version, confirmed adoption or recurrence. Do not run extra inference to demonstrate benefits. Actual optimization usage deduplicates against history using reliable measurement identity; unknown usage is not zero. Same-method text changes do not establish causal benefit.

## Startup, accounts and acceptance

Show the shell first and use actual discovery, reading, indexing and saving events without percentages lacking reliable denominators. Partial tasks are viewable before complete aggregates; completion preserves the open task. Stopping the page wait does not claim cancellation of shared scans. Separate absent sources, empty records, tasks without measurements and unmatched filters. Readable authorized files remain checkable.

Account identity, allowances and account summaries load and degrade independently; Codex owns login and credentials. Actual window periods, names, units and reset times are not fixed to five hours or seven days. Unknown, stale or past-reset values do not become full allowances. Unrelated model buckets cannot block requests; only fresh explicitly applicable limits influence them. Local usage and account allowances are neither converted nor added.

One global language control owns complete bilingual dynamic messages and quantity-aware English units. Closing windows, access denial, full disks, disconnections and unknown formats preserve explicit states and usable prior results. The unreleased first version maintains only current formats without old-page, protocol, index or database migration. Reject unknown formats while retaining data.
