# Wombat 文档维护

此 Skill 是文档工作流程，不定义产品功能。先读仓库及目标目录的 `AGENTS.md`；文档分层以 [docs/AGENTS.md](../../../docs/AGENTS.md) 为准，配对及术语以[双语流程](../../../docs/i18n/README.md)为准。

1. 确定读者和任务：用户操作、开发参考、模块接口、目标方案、当前范围、阶段状态、历史验证或持久决策。找到主要归属文件；模块契约放对应 README，决定理由按[决策记录约定](../../../docs/decisions/README.md)保存，避免同主题副本。
2. 对照源码、生成契约、现有测试和带日期的证据，列出本次能确认的事实。运行步骤只有在当前构建实际验证后才能写成可用说明。
3. 先更新主要归属，再更新入口链接和受影响的支持矩阵、实施跟踪或进度。历史证据保留日期与测量条件；未完成事项留在目标或跟踪文档。
4. 日常双语修改先读术语表，只翻译改变的段落并保留未变译文；不自动启动额外翻译代理。章节哈希报错时核对对应章节，不能无审校重录。对已配对页面，按术语表同步修改另一语言，保持标题层级、列表、代码块和链接语义；人工核对含义后执行 `corepack pnpm docs:i18n:record -- <中文文件>`。既有未配对页面迁移时补齐完整配对，不把机器校验当成译文审校。
5. 检查本地引用、私有资料边界和文档状态是否一致。执行 `corepack pnpm docs:check` 与 `git diff --check`；公开包内容仅在发行范围变化时用 `corepack pnpm public:check --package` 检查。
6. 报告改了哪些页面、用什么证据确认、哪些操作或平台仍未验证。

当代码和文档冲突时，先确认当前代码及实际运行结果，再修正文档；不把本 Skill 或历史进度当作实现证据。
